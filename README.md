# Navolta Projektcontrolling – GitHub Pages ohne Firebase

## Veröffentlichung
1. ZIP entpacken.
2. Auf https://github.com/new ein Repository `navolta-projektcontrolling` erstellen.
3. Für GitHub Pages im kostenlosen öffentlichen Repository **Public** auswählen.
4. Im Repository **Add file → Upload files** wählen.
5. Die entpackten Dateien (`index.html`, drei PNG-Dateien, `.nojekyll`, `README.md`) hochladen. **Nicht nur das ZIP hochladen.**
6. **Commit changes**.
7. **Settings → Pages → Build and deployment**: `Deploy from a branch`, `main`, `/(root)` → **Save**.
8. Website nach der Veröffentlichung öffnen: `https://DEIN-BENUTZERNAME.github.io/navolta-projektcontrolling/`.

## Wichtige Einschränkungen
- Dies ist die bestehende vollständige **Offline-HTML-Anwendung**, die auf GitHub Pages bereitgestellt wird.
- **Ohne Firebase oder einen anderen Server gibt es keine gemeinsame Datenbank und keine echte Synchronisierung zwischen Mitarbeitenden.**
- Daten und hochgeladene Dateien werden weiterhin **lokal im jeweiligen Browser** gespeichert. Jeder Benutzer sieht eigene Daten.
- Daten sind möglicherweise auch je nach ursprünglicher Dateiadresse/Browser nicht automatisch in der Online-URL sichtbar. Vorher Daten sichern und bei Bedarf importieren.
- **Keine** Kundendaten, Rechnungsdateien, Passwörter oder privaten Unterlagen ins öffentliche GitHub-Repository hochladen.
- Für echte Zusammenarbeit braucht es später eine zentrale Datenbank (Firebase, Supabase, eigener Server o. Ä.).
- Die Bereitstellung über GitHub Pages wurde nicht live getestet.
